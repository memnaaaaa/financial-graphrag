GOLDEN SET (data/questions.jsonl) - how the gold chunk ids are made
===================================================================

Status: 1 of 19 questions validated by an independent LLM labeler (q01).
        q02-q19 use pattern-matched labels that are NOT yet verified. All numbers are preliminary.

Types: 9 single-fact, 5 multi-hop within one company, 5 cross-company.

 [a] PATTERN LABELS (all questions)
     gold = every chunk in the named company + fiscal-year filing whose text matches a label+number pattern
     (scripts/build_questions.py)  ->  data/questions.jsonl, backup kept in data/questions_pattern_gold.jsonl
        │
        ▼
 [b] CANDIDATE POOLS (scripts/build_label_pools.py)
     per question: top chunks from bge-small + DistilBERT + BM25, restricted to the filings the question names
     + 8 off-target chunks (other years/companies); shuffled; no reference answer
     40 chunks (single filing) or 72 chunks (two filings)  ->  data/labeling/qNN.txt   (not stored in the repo)
        │
        ▼
 [c] OTHER LLM (different model family) + data/labeling/PROMPT.txt
     labels every chunk: answer / supporting / irrelevant, with a verbatim quote for each "answer"
     one chat per question  ->  JSON reply saved as data/labeling/replies/qNN.json
        │
        ▼
 [d] VALIDATE (scripts/ingest_labels.py)
     accept only if: every candidate labeled once, quote found verbatim in the chunk and contains a figure,
     chunk is from the company + fiscal year the question names
        │
        ▼
 [e] APPLY (--apply): validated "answer" chunks replace the gold set in data/questions.jsonl
     (gold_source = "llm-labeler (validated)"); the rest stay "pattern-match (unverified)"


Run 2 results (19 questions, mixed gold) - main findings
========================================================

  - Retrieval never picks the wrong company, but picks the wrong fiscal year of the right company 43% of the time.
  - Cross-company questions: both companies' answer chunks found for only 0-1 of the 5 questions in every config.
  - When a gold chunk is retrieved, the answer is judged correct only 47-64% of the time.
  - Rerunning gave identical retrievals and answers (0/152 changed); 1 of 152 judge verdicts flipped on the same text.
