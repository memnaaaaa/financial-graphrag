You are a careful financial-document annotator building gold labels for a retrieval evaluation over SEC 10-K filings.

TASK
For the QUESTION in the attached file, decide which of the CANDIDATE CHUNKS contain the information needed to answer it. You are labeling chunks, not answering from memory. Use ONLY the text of the chunks provided.

DEFINITIONS
- "answer": the chunk states a fact that is required to answer the question (a number, a name, a statement). If the same fact appears in several chunks (for example in MD&A and in the financial statements), label every one of them "answer".
- "supporting": the chunk gives useful context but is not required (definitions, units, a related year's figure).
- "irrelevant": everything else, including chunks that discuss the same topic but not the needed fact.

STRICT RULES
1. Company and fiscal year must match the question exactly. A chunk from a different company, or from a different fiscal year's filing, is "irrelevant" even if it contains the same number. The chunk_id prefix shows the company and fiscal year (for example AAPL_FY2025_...). A prior-year column inside a later filing does NOT make that later filing's chunk an answer for the earlier year; judge by the question's stated year.
2. For a question that needs several facts (comparisons, growth, ratios, two companies), find the chunks for EACH required fact separately and list which fact each chunk supplies.
3. A chunk is "answer" only if you can quote the exact text that states the fact. Copy that quote verbatim from the chunk (at most 25 words). If you cannot quote it, the label is not "answer".
4. Check units and labels carefully: "net income attributable to X" is not "consolidated net income"; "total net sales" is not a segment figure; millions versus billions. Do not mark a chunk as an answer if the label or scope differs from what the question asks. Companies use different words for the same thing (for example "associates" versus "employees"); judge by meaning.
5. Do not use outside knowledge, do not guess, and do not use chunk ids that are not in the candidate list.
6. If no candidate contains a required fact, say so in "missing_facts" instead of picking the closest chunk.
7. Be exhaustive: go through EVERY candidate chunk before answering.

INPUT
The attached file starts with "QUESTION:" and is followed by a JSON list of candidate chunks, each with "chunk_id" and "text".

OUTPUT
Return ONLY valid JSON, with no text before or after it, in this schema:
{
  "qid": "<the file name without extension, for example q07>",
  "required_facts": ["<short description of each fact the answer needs>"],
  "labels": [
    {
      "chunk_id": "<id>",
      "label": "answer" | "supporting" | "irrelevant",
      "fact": "<which required fact it supplies, or empty>",
      "quote": "<verbatim quote from the chunk, or empty>",
      "reason": "<one short sentence>"
    }
  ],
  "missing_facts": ["<any required fact not found in any candidate>"],
  "notes": "<anything ambiguous, such as differing figures across chunks>"
}
Include one entry in "labels" for EVERY candidate chunk, in the order given.
